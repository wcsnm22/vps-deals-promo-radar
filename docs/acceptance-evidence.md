# Acceptance evidence for the daily-benchmark loop

Generated by a one-off check; every line below is measured, not asserted.

## 1. Daily automation exists and publishes

| Item | Evidence |
|---|---|
| Scheduler entry | Windows Task `vps-deals-daily`, DAILY at 09:00, `NextRunTime = 2026-09-22 09:00` |
| Entry point | `daily-run.cmd` (ASCII-only, uses `%~dp0`) -> `daily.py` |
| Stages run | scraper -> guides -> build -> content_check -> deploy -> verify_deploy |
| Last result | `LastTaskResult = 0` |
| Runs logged | 21 rows in `data/daily-log.jsonl`, every one `status: ok` |
| Once-per-day guard | first run of the day raised guide count 3 -> 4; the remaining 18 runs all logged `[skip] an auto guide for 2026-09-21 already exists` and the count stayed 4 |

## 2. One page per day, one gap per page

| Item | Evidence |
|---|---|
| Gap rotation | `csv -> unitprice -> steps`, chosen by which gap has been used least |
| Pages live | 4 guide pages: `vps-comparison-table-csv` (csv), `how-vps-pricing-works` (unitprice), `how-to-buy-and-connect-a-cheap-vps` (steps), `csv-2026-09-21-1` (csv, auto) |
| Multi-day proof | 12 consecutive simulated days each produced exactly one page, gaps rotating, distinct titles |
| Unique subject | each page takes a different provider from our own data, so numbers/tables differ per day |

## 3. First screen answers; >=30% exclusive; nothing copied

| Item | Evidence |
|---|---|
| Checker | `content_check.py`: lede must carry a digit, 5-gram overlap vs the benchmarked corpus must stay under 30%, no CJK residue, no video/channel traces |
| Result | 4/4 pages pass |
| Overlap corpus | 56,293 n-grams built from the three benchmark domains' top pages fetched during BENCH |
| Gate | `daily.py` only publishes when the checker exits 0; otherwise the live site keeps the previous build |
| Recomputation | every lede number is recomputable from `data/offers.json` / the CSV (e.g. `47.95 EUR / 64 GB = 0.7492`) |
