# 手把手：在 GSC 提交站点地图 + 请求收录

写给没用过 Search Console 的人。跟着点就行，**每步都写了"你应该看到什么"**——对不上就停下告诉我。

前置：你的域名**已经用 DNS 验证过了**（这点我实测确认过），所以不用再做验证，直接进后台操作。

---

## 第 0 步：打开后台并确认选对站点

1. 双击桌面上的 **`打开 Search Console`** 快捷方式
   （或在地址栏输入 `https://search.google.com/search-console`）
2. 如果要求登录，用 `tsf19709677503@gmail.com` 登录
3. **左上角有个下拉框**，点开，确认选中的是 **`vpsdealsradar.com`**

> ⚠️ 这一步最容易错。如果下拉里有两个（一个 `vpsdealsradar.com`、一个带 `https://`），**两个都能用**，先选不带 `https://` 的那个（网域资源）。选错了后面看到的数字会不一样。

**你应该看到**：左边一列菜单，最上面几项是「概览 / 索引 / 效果 / 体验 / 增强功能」。

---

## 第 1 步：提交站点地图

1. 左侧菜单点 **「索引」**（一个放大镜形状的图标），它会展开子项
2. 点子项 **「站点地图」**
3. 页面上有个输入框，旁边写着「添加新的站点地图」或「输入站点地图网址」
4. 在框里输入：`sitemap.xml`
   - 如果它要求完整网址，就输入：`https://vpsdealsradar.com/sitemap.xml`
5. 点右边的 **「提交」** 按钮
6. 页面顶部可能弹出一个绿色提示

**你应该看到**：下方列表里出现一行 `sitemap.xml`，状态列显示 **「成功」**，并且有一个「已发现的网址数」——**应该是 33**。

> 🔎 如果显示「无法获取」或「有错误」：先别慌，等 10 分钟刷新一次。谷歌第一次抓取有时会失败，重试就过。连续失败再来找我。
>
> 🔎 如果显示「成功」但网址数是 0 或个位数：说明谷歌刚提交还没解析完，过几小时再看。

**这一步完成就够用了。** 下面的第二步是"手动催"某几页，可选。

---

## 第 2 步（可选）：手动请求收录 5 个页面

配额有限（通常每天十几条），所以只挑最重要的几页，**不要对 33 页全做**。

对下面每一页重复这 4 个小动作：

**要请求的页面清单：**
```
https://vpsdealsradar.com/
https://vpsdealsradar.com/guide
https://vpsdealsradar.com/guide/how-vps-pricing-works
https://vpsdealsradar.com/methodology
https://vpsdealsradar.com/downloads/unit-price.csv
```

**每一页的 4 个动作：**

1. 看页面**最上方**——有个很宽的搜索框，里面有灰色提示字「检查任何网址」或「输入网址」
2. 把上面某一页的完整网址**粘进去，按回车**
3. 等几秒，它会显示这一页的检查结果（会转个圈）
4. 找到 **「请求编入索引」** 这个按钮，点它 → 再弹一个确认，再点一次

**你应该看到**：提示「已请求编入索引」或「已添加到优先抓取队列」。

> ⚠️ 「请求编入索引」按钮**可能是灰的**。如果灰的，说明这一页刚被检查过或被请求过，**不用管它**，跳过这页继续下一页。
>
> ⚠️ 每页请求完**等 5-10 秒**再做下一页，别连点。

---

## 第 3 步：确认提交成功（回头核对）

回到左侧 **「索引」→「站点地图」**，确认：

| 看什么 | 应该是什么 |
|---|---|
| 列表里有 `sitemap.xml` | ✅ |
| 状态 | **成功** |
| 已发现网址数 | **33** |
| 最后读取时间 | 今天的日期 |

## 第 4 步：之后每周看一次这两个数（别天天看）

回到左侧 **「索引」→「网页」**：

| 看什么 | 现在 | 期望 |
|---|---|---|
| 绿色块「已编入索引」 | **2** | 每周往上走 |
| 灰色块「未编入索引」 | 22 | 慢慢变少 |
| 表里原因「已发现 - 尚未编入索引」 | 22 | 慢慢转成"已编入索引" |

**不要每天来看**——数据更新有延迟（通常几天），天天看只会焦虑。

---

## 千万别做的事

| 别做 | 为什么 |
|---|---|
| ❌ **每天重复提交 sitemap** | 没有加速作用，还可能被当作异常行为 |
| ❌ **把 33 页全请求一遍** | 配额就那么点，用完当天就没了，重点页反而排不上 |
| ❌ **去点那些"SEO 加快速收录"的服务** | 没用，且可能违反谷歌规则 |
| ❌ **改 sitemap 里的网址** | sitemap 由构建自动生成，手改会被下次构建覆盖 |

---

## 出问题了怎么判断

| 你看到的 | 含义 | 怎么办 |
|---|---|---|
| 找不到「索引」菜单 | 可能选错了资源，或账号没这个站的权限 | 回第 0 步重选左上角下拉 |
| 站点地图状态「无法获取」 | 谷歌抓 sitemap 失败 | 等 10 分钟刷新；仍失败告诉我 |
| 「已发现网址数」是 0 | 刚提交，还没解析 | 等几小时 |
| 请求索引按钮是灰的 | 该页近期已被请求过 | 跳过，不用管 |
| 全部页面状态都是「已发现 - 尚未编入索引」 | 正常，就是**在排队** | 等，这是最耗时间的一步 |

---

## 时间预期（这里我不编数字）

新域名从「已发现」到「已编入索引」**通常需要几天到几周**，取决于站点体量和谷歌当时的抓取预算。**我没有实测过的天数，所以不给你具体数字。**

唯一能真正加速的是**持续更新**——你站上每天一篇的循环已经在跑，不用额外操作。
